The key the codes are stored under

Every stored invitation is a hash computed under one key. Rotating it makes all of them unverifiable at once, so no invitation minted before the rotation can be redeemed again. It is the answer to a key that has leaked, and it is not something to press to tidy up. No account is touched and no record is removed.

The count of what it would invalidate is read from the server and shown before anything is written.

Settings

The address a stranger reaches this server on, written the way a browser outside your network would need it, scheme and all. Invitation links are built from this and never from what a request says the host is, because a request can say anything. Left empty, building a link is refused rather than guessed at.

Numbers

Three numbers an operator may set. Each has a maximum this plugin compiles, and the maximum is what carries the promise: a value you type can tighten what the plugin does and can never loosen it past the number the source already holds. A value outside its range is refused where it would be used rather than replaced by the plugin’s own, so the sweep removes nothing or a redemption is refused until it is repaired, and the server log names the setting when the plugin loads.

From 1 to 3650. How long a spent, expired or revoked invitation is kept before the nightly sweep removes it. An invitation that can still be redeemed is never removed, whatever this says. Shorter holds less about who was invited; longer keeps the answer to where an account came from available for longer. One day is the floor because zero would delete the record the day it stops being usable, before anybody could read it.
From 1 to 20, and 20 is the compiled maximum, so this can only be lowered. Opening the setup page is not an attempt and a refused request is not one. Set it low and people behind one shared address or one reverse proxy refuse each other.
From 1 to 10, and 10 is the compiled maximum, so this can only be lowered. It bounds every source at once, which is the limit that keeps meaning something when somebody has many addresses.

Account templates

The named grants an invitation is minted against. What an invitation carries is a copy of the entry as it stood when it was minted, so editing one here changes the next invitation and none already sent. The templates are saved with the settings, by the button at the bottom.

  • Every template needs a label, without a space at either end, and no two labels may be the same once case is ignored.
  • A library is named once, and the all-zero identifier names no library. A template naming no library is a template somebody chose, and it is saved as written.
  • A ceiling is a whole number of at least zero. Left empty, there is no ceiling.
  • One entry breaking a rule refuses the whole list when the plugin loads, and the refusal in the server log names the position of the entry and the rule it missed. Nothing on this page judges these rules, so a save that breaks one is accepted here and refused there, and nothing is minted until it is repaired.
  • No template can ask for an account that manages the server. There is no control for it here and no member for it in the setting.
